# Long-Term Project Progress Model

**Status:** Phase 2 World Engine model established
**Baseline:** 1 Harvestfall, 243 AC
**Execution:** GM-reviewed

## Purpose
Allow actors to pursue goals over weeks, months, and years without requiring every project to become an immediate event.

## Project state
Each project may track:
- sponsor;
- objective;
- status;
- stage;
- dependencies;
- resources required;
- blockers;
- participants;
- affected issues;
- recent progress;
- next decision point;
- expected consequence;
- visibility;
- source records.

## Status vocabulary
- PROPOSED
- CONSIDERING
- APPROVED
- UNDERWAY
- BLOCKED
- DELAYED
- COMPLETED
- ABANDONED
- DISPUTED
- MONITORING

A project may move backward when a dependency fails or a political decision reverses it.

## Progress rules
1. Projects consume time and attention.
2. Projects depend on people, materials, money, authority, access, and information as appropriate.
3. A project does not automatically succeed because its sponsor wants it.
4. A project does not automatically fail because it is difficult.
5. Blockers and delays should be recorded explicitly.
6. Completed projects create world-state consequences.
7. Projects may generate new issues, relationships, or events.

## Existing baseline projects
The current state already records local Tallowmere projects and continental projects including:
- Northern Watch autumn provisioning;
- Edarth banner rolls and service review;
- Crownland road and courier service review;
- Western Pass commercial terms review;
- Eastern Coast pilotage and harbor-practice review;
- Brightwater river-market charter review.

These projects remain the initial project register rather than an invented schedule.

## Evaluation
**objective → dependencies → progress/blocker → decision → consequence**

Long-term projects should be evaluated when their timing, dependencies, or external events make them relevant.
