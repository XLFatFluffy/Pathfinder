# World Fork Model

**Status:** Phase 3 model established
**Baseline:** 1 Harvestfall, 243 AC
**Execution:** GM-reviewed

## Purpose

Identify moments where accumulated world conditions make materially different futures plausible.

A fork is a decision point, not a prediction.

## Fork record

Each fork may contain:

- fork ID;
- trigger conditions;
- affected actors;
- affected systems;
- current state;
- plausible path A;
- plausible path B;
- additional plausible paths where justified;
- evidence supporting each path;
- conditions that would favor each path;
- information visibility;
- GM status;
- resulting event IDs once resolved.

## Fork states

- **DORMANT:** conditions are not yet sufficient.
- **EMERGING:** multiple outcomes are becoming plausible.
- **PRESENTED:** the fork is significant enough for GM review.
- **APPROVED:** GM selected a direction.
- **REJECTED:** GM rejected the proposed fork.
- **DEFERRED:** decision remains open.
- **RESOLVED:** events have established an outcome.
- **SUPERSEDED:** the fork no longer applies because prior state changed.

## Rules

1. Do not manufacture forks for ordinary uncertainty.
2. Do not create a fork merely because two outcomes are imaginable.
3. A fork requires materially different consequences.
4. A fork should emerge from existing actors, constraints, information, projects, issues, or environmental conditions.
5. The engine must not secretly choose a major future merely to preserve dramatic surprise.
6. If the GM allows the engine to resolve a fork, the resolution becomes an explicit historical event.

## Major-twist rule

A major transformation must arise from accumulated state and plausible causes. It cannot be inserted solely because the campaign needs a dramatic moment.
